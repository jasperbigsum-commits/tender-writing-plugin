# 要求驱动的投标目录

读取 [数据契约](../bid-writing/references/data-contract.md)、项目主数据与全部现行要求。目录优先遵循招标给定的结构、分卷顺序、附件与制式表格，其次覆盖评分项，再安排通用说明。

为章节分配稳定 `Cxxxx` ID，以 `parent_id`、`order` 表示树形结构。每个强制要求和评分项须关联 `requirement_ids`；同一要求需要多处响应可以关联多个章节。父章节可仅作容器，叶子章节必须有正文或明确待填项。不要用复制标题替代实质覆盖。

对每个叶子章节在 `outputs/writing-plan.md` 写明：本章回答的问题、关联要求和评分项、必要证据、拟采用历史模块、具体写作内容和篇幅。篇幅服从招标限制与内容需要；没有要求时不用“越长越好”或固定两百页。

运行 `matrix` 查漏后直接进入可写章节。目录调整时保持 ID 及来源关联，检查是否有孤立正文、失效要求、跨包混用和父子循环。目录中含身份的标题同样需要暗标检查。
