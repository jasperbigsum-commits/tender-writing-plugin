# 企业资料与历史模块

先阅读 [运行手册](../bid-writing/references/cli.md) 和 [证据契约](../bid-writing/references/data-contract.md)。

1. 每个投标主体建立独立资料库，使用 `library-init`。通过 `library-add` 导入用户指定原件，分类为 certificate、case、person、product、module，并补充检索标签和可确认的有效期。
2. 对照原件提取证照名称、编号、持有人、适用范围、有效期、相关产品版本。历史项目记录客户、履约内容和可证明成果。没有证据的内容保持未知，不从企业名称推断资质。
3. 历史标书拆成可复用模块，记录来源与原项目限制。历史报价、客户名称、旧时间和旧承诺不能直接继承到新项目。引用图表还要核对图片、权利及适用性。
4. `library-search` 是名称、类型和标签的关键词检索，不是向量检索。结合招标要求筛选；需要全文判断时直接阅读抽取文件，不能把未搜到等同于资料不存在。
5. `library-use` 只将选中原件导入项目，不会自动把它认定为有效证据。阅读新的 `Sxxxx` 文件，向 `evidence.json` 写入精确原文定位、投标主体和状态；实际核验后才标 `verified`。
6. 用相关日期重新核验有效期。长期有效须填写原文支持的 `validity_note`；未确定到期日期不能假装长期有效。

输出资料台账、到期与缺件清单、本次采用模块和来源。将复用材料继续保留在项目快照中，资料库后续变化不静默修改已生成文件。脚本目前没有多人权限系统；需要组织级隔离时使用宿主文件权限和独立资料库。
