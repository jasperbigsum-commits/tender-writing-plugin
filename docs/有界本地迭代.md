# 有界本地迭代（RSI 最小工程闭环）

## 适用性与边界

本插件目前是技能说明与本地文档工具，不是模型训练系统。现有测试能检查证据、引用、人工复核、路径与导出状态，不能证明标书质量或中标率。因此本实现是**本地候选选择循环**，不是声称模型会无限自我提升：

固定基线与目标测试 → 逐个候选 → 独立回归与目标评测 → 严格改善才保留 → 无改善回退 → 写记录 → 到预算停机。

没有新增模型提供方、API key、第三方 agent、自动下载、自动提交、自动发布或自动合并。候选由人或已获授权的编码任务准备。没有候选/目标测试时，不能凭空“自动修复”。业务审核不由评分替代；缺失证据、人工复核等合法 blocker 不应作为优化目标去删除。

## 与参考项目的关系

- [autoresearch](https://github.com/karpathy/autoresearch)：借鉴固定评估与 keep/discard 记录，不采用无限循环或放宽权限。
- [OpenEvolve](https://github.com/algorithmicsuperintelligence/openevolve)：借鉴有限迭代、早停与记录，不引入其模型依赖、种群或外部服务。

这是独立实现，没有复制或执行这些项目的代码。

## 使用方法

运行器是开发工具，不打入技能插件 ZIP。需要 Python 3.10+ 和 POSIX（Linux/macOS）；Windows 目前可使用 WSL。Windows 原生进程组超时未实现，因此拒绝运行，而不是假装能安全终止后代进程。

1. 在不含凭据、生产资料、真实标书的临时环境准备可信仓库副本。
2. 由审阅者先写独立的 `test_*.py` 目标测试，放在仓库外一个目录中，文件名不要和原回归测试重名。用环境变量 `RSI_CANDIDATE_ROOT` 找到候选根目录，使用 unittest。目标必须是具体可验证缺陷，不应是“减少业务阻断数”。目标测试既要验证改善，也要覆盖相关禁止行为。
3. 准备最多三份完整候选 `bidflow.py` 文件。每份均相对于同一基线，后续候选若希望累计前次修复，需要显式包含前次修复。候选不能替换其他文件、改测试、改审核规则文档或评分器。
4. 在已经安装项目测试依赖的环境运行：

```bash
python tools/rsi_loop.py \
  --objectives /tmp/tender-objectives \
  --candidate /tmp/candidate-1.py \
  --candidate /tmp/candidate-2.py \
  --candidate /tmp/candidate-3.py \
  --out /tmp/tender-rsi-run-001
```

输出目录必须不存在且在源码与目标测试目录之外，避免覆盖历史结果或递归复制。`--source` 可指定另外的基线仓库。

## 判定与停机

- 默认最多 3 轮，连续 2 轮不提升早停，单次评估 120 秒，总评估流程预算 600 秒。
- 可调参数：`--rounds` 1..10、`--patience` 1..轮数、`--timeout` 最大 300 秒、`--budget` 最大 1800 秒。预算含基线；文件复制、日志写入等开销不属于硬实时保证。
- 基线回归必须全通过、无跳过、无预期失败；目标必须非空，允许断言失败，但不允许测试错误、跳过或预期失败。否则停机，不能用坏基线声称改善。
- 候选回归同样必须全通过，测试数保持一致；目标失败数必须严格下降、目标测试数一致，才保留。
- 目标全部满足、预算耗尽、连续无提升或候选用完均停止。没有随机循环或隐藏重试。
- 每轮由冻结副本运行评分驱动和目标测试，另复制基线回归测试。运行前后校验驱动、目标和回归测试文件的哈希；变化会拒绝该候选并立即终止整轮流程。
- 超时终止评估进程组；失败/无改善不覆盖前次最佳候选。

## 结果

`report.json` 记录预算、基线、目标文件 SHA-256、每轮输入 SHA-256、测试计数、keep/discard 与停机原因。每轮有独立目录和 `evaluation.log`。若有提升，`accepted-bidflow.py` 是保留的**输入候选**，不是测试运行后可能变更的文件。

脚本从不覆盖源仓库、不创建 commit、不调用 GitHub。人工检查差异及业务语义，再运行全部测试、打包、demo 和 Word 版式检查后，才可通过正常 PR 审核接纳。通过测试不是发布授权。

## 安全与已知限制

**副本隔离不是安全沙箱。** Python 候选与测试具有当前用户权限，哈希检查防误修改而非防恶意代码；恶意代码仍可能篡改报告、访问网络或同机文件。只运行自己审阅的可信本地候选。不要把不可信下载代码交给本脚本执行。需要自动生成与执行不可信候选时，应先加入真正的无网络、只读评估器、无秘密、限 CPU/内存/磁盘的容器/虚拟机边界，不能把本脚本当成这个边界。

进程不继承 API key、token、代理或 Python 启动环境，副本排除 `.git`、`.env*`、临时目录、项目数据与常见输出，拒绝符号链接。但这些措施不保证发现所有秘密文件；运行前仍需人工检查干净工作区。当前没有硬内存/磁盘配额，异常退出时报告可能保留为中断态。自动选择仅覆盖单个 `bidflow.py`，不改变技能文案、依赖或评估基础设施。

目标测试必须预先独立定义，不能在看完候选后随意放宽以“得高分”。当前没有真实标书质量基准、盲测集、成本评估或自动生成器，不应宣传为已实现开放式递归自我改进。

## 本轮验证记录

- 新增 15 项机制测试：改善/退化/完成、保留最佳、轮数上限、总预算、评估超时、坏基线、符号链接、输出防覆盖、参数边界、空目标、已达目标、评估器改动拒绝。
- 联合业务回归共 50 项通过；插件构建校验通过。仅实测本地 Python 3.12 / Linux，其他平台和远程 CI 未实测。

- 上述两个目标来自已知缺陷，是机制验证，不是盲测质量提升证据。未调用模型、未生成新的业务修复、未替换源文件、未自动发布。
